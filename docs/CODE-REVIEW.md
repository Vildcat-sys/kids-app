# Code Review 检查清单

## 零、审查者的心态

Code Review 不是找茬，是**把知识从一个人脑子里搬到团队里**。

三条原则：

1. **先跑再评**。拿到 PR 第一件事是 `npm run check` **加上 `npm run check:media`**，别用眼睛代替机器。
2. **区分「必须改」和「可以更好」**。前者只有：正确性、内容安全、依赖方向。其余都是建议，标注清楚，让作者决定。
3. **评论要给理由**。「这里不好」没有价值，「这里会让离线状态白屏，因为 sw.js 没覆盖」才有。

## 〇之二、五闸与它们的退出码

本项目有**五条独立的闸**，退出码分开 —— 这样才能分清「代码写错了」还是「素材还没做」。

| 闸 | 命令 | 查什么 | 归谁管 |
|---|---|---|---|
| 结构校验 | `npm run validate` | 内存里的数据形状（落位、题目、插画 key） | 内容 |
| 单元测试 | `npm test` | 行为契约（分级、课程矩阵语义、store、prefs…） | 开发 |
| 死代码与离线清单 | `npm run check:reach` | 入口可达性（有没有没人 import 的文件）+ `sw.js` 的 ASSETS 双向核对 | 开发 |
| 媒体完整性 | `npm run check:media` | **磁盘上的文件在不在**（旁白 / 题目音 / 绘本图 / 封面） | 内容 + 素材 |
| **插画质量** | `npm run check:art` | **图合不合格**：分辨率下限 / 同一知识点三页是否互不相同 / 封面是否复用内页 / 代码里的图片路径是否可达 / 有无 0 字节残留 | 内容 + 素材 |

**注意**：`npm run check` **只跑前两条**（`validate && test`），故意不含后三条 —— 因为死代码和媒体缺口不该挡住开发者提交代码。**但出包前五条必须全绿。**

```
npm run check         # 开发期：结构 + 单测
npm run check:reach   # 提交前：死代码 + 离线清单
npm run check:media   # 出包前：素材齐不齐
npm run check:art     # 出包前：图合不合格
npm run check:all     # 一次性跑全部五条
```

**为什么要第五条**：前四条都不管"图长什么样"。曾出现过 18 个知识点的
**三页绘本用同一张图、封面又是这张图的第 4 份副本、分辨率只有老板块的 1/4** ——
`check:media` 只数文件个数（480/480 ✓），四条全绿，问题一个都没抓到。
**「文件在」和「文件对」是两件事。**

## 三、常见反模式

### ❌ 用 `innerHTML` 拼内容

```js
// 坏：内容将来可能由非开发同学维护，拼字符串容易漏转义
el.innerHTML = `<div class="fact">${item.facts[0]}</div>`;

// 好
h('div', { class: 'fact' }, item.facts[0]);
```

例外：内联 SVG 必须用 `html` 属性，这是明确允许的。

### ❌ 题型模块直接改进度

```js
// 坏：绕过了 ui/quiz.js 的统一路径，将来加统计会漏掉这条
import { store } from '../core/store.js';
store.markLearned(item.id);

// 好：上报结果，由容器统一记录
api.onAnswer({ correct });
```

### ❌ 用 `Math.random` 打乱选项

见 `docs/ARCHITECTURE.md` 第四节第 5 条。用 `seededShuffle`。

### ❌ 同元素叠类时用简写

```css
/* 坏：<div class="wrap detail"> 时，这里的 0 会吃掉 .wrap 的左右内边距 */
.detail { padding: 22px 0; }

/* 好 */
.detail { padding-top: 22px; padding-bottom: 22px; }
```

这个坑真实踩过：详情页内容贴到屏幕边缘，看起来像溢出，实际是边距丢失。诊断花了三轮才定位到。

### ❌ 用固定时长等待异步渲染（写测试时）

```js
// 坏：渲染时机不确定，测试会随机失败
await sleep(300);

// 好：轮询到条件满足为止
waitFor(() => q('.opt'), () => { /* 继续 */ });
```

### ❌ 让错误静默失败

```js
// 坏：出错时孩子只看到「点了没反应」，家长也说不清哪里坏了
const quiz = item.quiz;

// 好：给出可读的提示
if (!type) {
  renderFallback(`未知题型「${quiz.type}」，请检查内容数据`);
}
```

### ❌ 静默回退到「空壳」

```js
// 坏：形状不符就悄悄换成一个「有板块、没内容」的替身，
//     于是孩子看到「准备中」，没人知道数据其实坏了
try {
  const mod = await import('../data/curriculum.js');
  if (shaped(mod)) return mod;
} catch (e) { /* 预期内 */ }
return buildShim();          // ← 空壳
```

回退（fallback）是给**不可控的外部依赖**用的（网络、传感器）。**自己仓库里的模块不该有回退** —— 它坏了就应该炸出来。

判据：**这个回退分支，有没有可能在某天悄悄生效、而没人发现？** 如果会，就别写。

> 真实案例：`src/ui/curriculum-api.js` 的这条回退分支，在 `curriculum.js` 落地后就变成了「谁 import 它，谁拿到空课程，且不报错」。

### ❌ 用「登记」代替「存在」（单向断言）

```js
// 坏：只查「每个 src 文件都被登记进 ASSETS」
for (const f of srcFiles) assert(ASSETS.includes(f));
// 删文件时忘了摘 ASSETS → 全绿，但运行时 add() 失败被吞掉
```

**登记表和磁盘是两回事，必须双向查：**

```js
// 好：登记 → 存在
for (const a of ASSETS) assert(existsSync(a), `sw.js 登记了不存在的 ${a}`);
// 好：存在 → 登记
for (const f of srcFiles) assert(ASSETS.includes(f), `${f} 没登记，离线时拿不到`);
```

同类陷阱：`ART[key]` 有没有登记 ≠ 那个 `<img src>` 指向的文件在不在。**只有专门查才抓得到。**

## 四、本项目特有的坑（血泪版）

这几条都是实际踩出来的，请重点看：

**1. 无头测试不能用 `async/await`**
Chrome 的 `--virtual-time-budget` 会快进 `setTimeout`，但**不会推进 async 函数的 Promise 续体**，`await` 之后的代码会全部丢失。写无头自动化测试时用纯回调链。

**2. 无头测试不能靠 `hashchange` 导航**
同一个原因，虚拟时间下 `hashchange` 事件不触发，iframe 里的页面会永远停在上一屏。测试要直接 import 模块同步渲染，不要走路由。

**3. 无头截图会「吃掉」入场动画，元素看不见但 DOM 里存在**
同一个原因——`--virtual-time-budget` 也**不推进 CSS 动画时钟**。凡是靠 `animation` 从 `opacity:0` 淡入的元素（本项目所有弹层 `.overlay` 都是），截图里会永远停在起始关键帧，渲染成**完全透明**。

这条最坑的地方是**排查方向会跑偏**：
- `--dump-dom` 里元素明明在，`querySelectorAll` 也能选到 → 于是怀疑是选择器、时序、模块加载
- 实际只是动画时钟没走

**判断方法**：`dump-dom` 有、`screenshot` 没有 → 先查该元素的 `animation` / `transition`，别查 JS。

**截图页面的写法**：在截图专用的预览页里直接关掉动画，生产 CSS 不要动：
```css
* { animation: none !important; transition: none !important; }
```

**4. 无头截图的输出路径必须是绝对 Windows 路径**
`--screenshot=".preview/x.png"` 会报 `系统找不到指定的路径 (0x3)`，即使当前目录就是项目根。写成 `--screenshot="D:\...\x.png"` 才正常。

**5. `node --test tests/` 在 Windows 上不工作**
必须用 `node --test`（自动发现模式）。`package.json` 里已经改好了，别改回去。

**6. 原生 ESM 不能用 `file://` 打开**
会直接被 CORS 拦截，页面全白。必须走 http 服务。

**7. 校验器的警告不要习惯性忽略**
「含空泛表达」这条警告上线当天就抓出了两条真实问题。警告是给内容质量兜底的，不是噪音。

**8. `--window-size` ≠ 真实 viewport（窄屏测试的假象）**
`--window-size=390` 时，Chrome 实际给页面的 `clientWidth` 是 **485**（有最小视口宽度），而 `--screenshot` 仍按 390 px 输出图片 → **右侧被裁，看起来像「移动端布局溢出」，纯属假象。**

窄屏测试正解：写一个 wrapper 页，用 `<iframe style="width:375px;height:1180px;border:0">` 包住被测页，再截 600 px 宽的窗口。iframe 里面才是真 viewport。

**溢出探针**（比肉眼可靠）：`load` 之后遍历 `body *`，报 `scrollWidth > clientWidth + 1` 的元素，但**排除 `overflowX: auto/scroll` 的滚动容器**（表格横向滚动是预期行为，不是 bug）。同时打印 `documentElement.clientWidth` 与 `scrollWidth` —— **两者相等即页面整体无横向溢出。**

**9. `--dump-dom` 数 DOM 元素，必须先剥掉 `<script>`**
内联 `<script type="module">` 里的模块源码会被当成 DOM 数进去，或者反过来，用 `<div id="app">(.*?)</div>` 这种正则会遇到嵌套 div 提前截断 —— **两种错法都会得出相反结论。**

```python
s = re.sub(r'<script.*?</script>', '', s, flags=re.S)
s = re.sub(r'<style.*?</style>',  '', s, flags=re.S)
n = len(re.findall(r'<[a-zA-Z][^>]*>', s))     # 这才是元素数
```

**10. 预览工装不要手写依赖桩，用真实模块**
`.preview/` 里的截图页曾经给 `speech` / `store` 手写桩。后来 UI 依赖面一扩大（`card.js` 加了 `speech.onStateChange`、`home.js` 加了 `store.getCoins`），薄桩就让 `renderXxx` 直接抛异常、**整页白屏**。

最坑的是：`--dump-dom` 看不出原因（元素确实没有），**只有截图是白的。**

```js
// 好：直接用真模块。headless 里 speechSynthesis 不支持，真模块本身就是安静的
import { createSpeech } from '../src/core/speech.js';
const speech = createSpeech();
```

用真模块就没有「忘了补哪个方法」这回事。

**11. 探针自己也会错 —— 反常数字先怀疑工具，但必须回去精确核对**
实测「目录里有 575 个旁白文件，但按知识点逐项累加只有 574」时，第一反应应该是**怀疑自己的脚本**（后来发现：确实是我的脚本漏了 1 个不符合命名的孤儿文件，而不是「有 1 个文件凭空消失」）。

但**不能只怀疑、不核对** —— 必须回去把两边都算清楚，才能判断是工具错还是数据错。这次核对的结果是**两个都有一点**：脚本漏检了，同时数据里真的躺着一个孤儿文件 `science-dinosaur.mp3`。

> 同一原则也适用于断言阈值：曾经把「CJK 字符数 > 6000」写成硬断言，实测 4688 判 FAIL；回查后发现 HTML 可见中文本来就只有约 4704 —— **是阈值拍错了，不是内容少了。**

**12. 两条独立实现交叉比对，比一条跑十遍有用**
`tools/check-media.mjs` 和临时探针是两套独立写的逻辑，最后都得出「155 条媒体缺口」，才对上了。**只靠一条实现，你会永远信任它的盲区。**

**13. 工装缺东西 = 假故障（同一个坑踩了两次）**
`.preview/` 下的工装是「子目录里的页面」，比生产页多两个易漏项：

| 漏了什么 | 症状 | 看起来像 |
|---|---|---|
| 漏引 `styles-kids.css` | 主题样式全丢，元素尺寸失控 | 「首页被三个图标撑满」= 产品布局崩了 |
| 漏 `<base href="../">` | `<img src="src/images/…">` 相对 `.preview/` 解析 → 404 | 「卡片上写着 `science-water-cycle`」= 产品没图标 |

**两次都表现为「产品有 bug」，两次都是工装自己的问题。**

工装的正确骨架（记牢，别每次重造）：

```html
<head>
<meta charset="utf-8">
<base href="../">                          <!-- ① 让站内路径从项目根解析 -->
<link rel="stylesheet" href="src/styles.css">        <!-- ② 注意：有 base 后不带 ../ -->
<link rel="stylesheet" href="src/styles-kids.css">   <!-- ③ 主题覆盖层，必须在 styles.css 之后 -->
<style>*{animation:none!important;transition:none!important}</style>
</head>
<script type="module">
import { renderHome } from '../src/ui/home.js';   /* ④ import 不受 base 影响，保留 ../ */
</script>
```

**判据**：工装截出来跟真实 `index.html` 不一致时，**先怀疑工装，再怀疑产品**。
最省事的对照法：同一屏分别截 `index.html` 和工装，拼一起看 —— 不一样就查工装缺什么。

**14. 改动批量文件前先写「自检脚本」**
给 7 个工装补样式表引用、补 `<base>`，这类机械修改不该手改 —— 手改一定漏。
写个脚本：**先扫一遍报出「缺什么」，改完再扫一遍报「还剩几个」**。两次输出对上，才算改完。

**15. 报文件体积用真实字节，不要用 `du`**
`du` 算的是**磁盘块对齐占用**（通常 4 KB 一块），不是文件真实大小。
小文件上偏差可达 3 倍 —— 实测 `du` 报 4.7 KB/张，`os.path.getsize` 只有 **1.70 KB/张**。

```bash
# 坏：块对齐，小文件被放大
du -sk src/images/art

# 好：真实字节
find src/images/art -name '*.webp' -printf '%s\n' | awk '{s+=$1;n++} END{print s/n}'
# 或 Python：os.path.getsize(f)
```

这条直接导致过一个错误结论：**「差 30 倍」实际是「差 80 倍」**。
数值结论写进报告/工单之前，先确认口径。

**16. 写进工单/文档的验收标准，必须先在现状上跑一遍**
曾经拍脑袋定了「模块数 ≤ 知识点数 / 2」当验收标准，
回查发现**老板块自己也不满足**（思维 25 模块 / 44 知识点 = 1.76）。
改成「单知识点模块占比 ≤ 50%」后，老板块 20–48%、新板块 60–80%，界线才干净。

> 判据：**一个「现状都不满足」的标准，等于没标准。**

**17. 并发修改时，任何测量结果都必须带时刻**
有另一个会话在同时改这个仓库时，文件会在你两次测量之间变掉。
实测过同一批图在 **90 秒内**走完 `480 张 → 476 张 → 480 张`，
`art-blue.webp` 从 `1542 B / 512×512` 变成 `127.4 KB / 2048×2048`。

**判据**：报告里写「X 张不合格」之前，先写清**测量时刻**。
否则你交付的不是结论，是一张过期快照 —— 而且它会和对方刚做完的工作直接矛盾，
让人以为你在挑刺。

推论：**别在对方明确说"我正在改"的时候下"最终结论"**。
改成给「可复跑的验收命令 + 当前快照」，让对方自己跑最新状态。

**18. 闸自己也会漏 —— 字符串路径要先展开常量，再判断**
扫描代码里的图片路径时，第一版是「先按字面量 `images/` 过滤，再展开常量」。
结果 `` `${BOOK_DIR}/${item.id}-0.webp` `` 这种写法**整条被漏掉** ——
它里面没有字面量 `images/`，展开后才是 `src/images/book/*-0.webp`。

正确顺序是**反的**：先把 `${常量}` 替换成字面量、把剩下的 `${...}` 换成 `*`，
**再**判断展开结果是不是以 `src/images/` 开头的文件路径。

同一条闸还有第二个自伤：文件缺失时用 `continue` 跳过，
于是「三页互不相同」的**分母跟着变小** ——
把 `book/` 只有 476/480 张的进行中状态，显示成了 `160/160 全绿`。
**缺页必须单独计入分母**，不能让它悄悄退出统计。

> 共同点：**闸的漏报往往不是"判断错了"，而是"根本没走到判断"**。
> 所以每条闸都该问一句：**它扫到的样本数，和我预期的一致吗？**

**19. `md5 不同` 不等于「内容合格」——判据有方向性**
「三页图 md5 相同」是**强判据**：相同就一定是同一张，一定错。
但反过来**不成立**：md5 不同可能只是把同一张图重新编码了一遍。

所以这条闸只能拦「明显没做」，拦不住「做了但敷衍」。
真正要确认内容对不对，**得把图转出来肉眼看**：
`art-blue` 那三页最后是这么确认的 —— 转出来是**蓝天草地 / 海浪海鸥 / 一碗蓝莓**，
和 `lead`（天空和大海）+ `fact2`（蓝莓）对得上，才算真过。

> 判据：**机器判"是否相同"，人判"是否对题"。** 两者都过才叫合格。
