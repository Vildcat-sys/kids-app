# Code Review 检查清单

## 零、审查者的心态

Code Review 不是找茬，是**把知识从一个人脑子里搬到团队里**。

三条原则：

1. **先跑再评**。拿到 PR 第一件事是 `npm run check`，别用眼睛代替机器。
2. **区分「必须改」和「可以更好」**。前者只有：正确性、内容安全、依赖方向。其余都是建议，标注清楚，让作者决定。
3. **评论要给理由**。「这里不好」没有价值，「这里会让离线状态白屏，因为 sw.js 没覆盖」才有。

## 三、常见反模式

### ❌ 用 `innerHTML` 拼内容

```js
// 坏：内容将来可能由非开发同学维护，拼字符串容易漏转义
el.innerHTML = `<div class="fact">${item.facts[0]}</div>`;

// 好
h('div', { class: 'fact' }, item.facts[0]);
```

例外：内联 SVG 必须用 `html` 属性，这是明确允许的。

### ❌ 题型模块直接改进度

```js
// 坏：绕过了 ui/quiz.js 的统一路径，将来加统计会漏掉这条
import { store } from '../core/store.js';
store.markLearned(item.id);

// 好：上报结果，由容器统一记录
api.onAnswer({ correct });
```

### ❌ 用 `Math.random` 打乱选项

见 `docs/ARCHITECTURE.md` 第四节第 5 条。用 `seededShuffle`。

### ❌ 同元素叠类时用简写

```css
/* 坏：<div class="wrap detail"> 时，这里的 0 会吃掉 .wrap 的左右内边距 */
.detail { padding: 22px 0; }

/* 好 */
.detail { padding-top: 22px; padding-bottom: 22px; }
```

这个坑真实踩过：详情页内容贴到屏幕边缘，看起来像溢出，实际是边距丢失。诊断花了三轮才定位到。

### ❌ 用固定时长等待异步渲染（写测试时）

```js
// 坏：渲染时机不确定，测试会随机失败
await sleep(300);

// 好：轮询到条件满足为止
waitFor(() => q('.opt'), () => { /* 继续 */ });
```

### ❌ 让错误静默失败

```js
// 坏：出错时孩子只看到「点了没反应」，家长也说不清哪里坏了
const quiz = item.quiz;

// 好：给出可读的提示
if (!type) {
  renderFallback(`未知题型「${quiz.type}」，请检查内容数据`);
}
```

## 四、本项目特有的坑（血泪版）

这几条都是实际踩出来的，请重点看：

**1. 无头测试不能用 `async/await`**
Chrome 的 `--virtual-time-budget` 会快进 `setTimeout`，但**不会推进 async 函数的 Promise 续体**，`await` 之后的代码会全部丢失。写无头自动化测试时用纯回调链。

**2. 无头测试不能靠 `hashchange` 导航**
同一个原因，虚拟时间下 `hashchange` 事件不触发，iframe 里的页面会永远停在上一屏。测试要直接 import 模块同步渲染，不要走路由。

**3. 无头截图会「吃掉」入场动画，元素看不见但 DOM 里存在**
同一个原因——`--virtual-time-budget` 也**不推进 CSS 动画时钟**。凡是靠 `animation` 从 `opacity:0` 淡入的元素（本项目所有弹层 `.overlay` 都是），截图里会永远停在起始关键帧，渲染成**完全透明**。

这条最坑的地方是**排查方向会跑偏**：
- `--dump-dom` 里元素明明在，`querySelectorAll` 也能选到 → 于是怀疑是选择器、时序、模块加载
- 实际只是动画时钟没走

**判断方法**：`dump-dom` 有、`screenshot` 没有 → 先查该元素的 `animation` / `transition`，别查 JS。

**截图页面的写法**：在截图专用的预览页里直接关掉动画，生产 CSS 不要动：
```css
* { animation: none !important; transition: none !important; }
```

**4. 无头截图的输出路径必须是绝对 Windows 路径**
`--screenshot=".preview/x.png"` 会报 `系统找不到指定的路径 (0x3)`，即使当前目录就是项目根。写成 `--screenshot="D:\...\x.png"` 才正常。

**5. `node --test tests/` 在 Windows 上不工作**
必须用 `node --test`（自动发现模式）。`package.json` 里已经改好了，别改回去。

**6. 原生 ESM 不能用 `file://` 打开**
会直接被 CORS 拦截，页面全白。必须走 http 服务。

**7. 校验器的警告不要习惯性忽略**
「含空泛表达」这条警告上线当天就抓出了两条真实问题。警告是给内容质量兜底的，不是噪音。

## 五、提交信息怎么写

```
<类型>: <做了什么>

<为什么这么做，以及有什么影响>
```

类型：`内容` / `题型` / `界面` / `核心` / `修复` / `文档`

例子：

```
内容: 生活科普新增「彩虹」

补了 1 个知识点和对应插画。顺带修正了「水循环」里一条事实的
表述，原文用了「很多」，按内容规范改成具体数字。

npm run check 全绿。
```
