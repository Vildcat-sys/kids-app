# 架构说明

## 一、分层与依赖方向

```
                        ┌──────────────┐
                        │   main.js    │  装配层：唯一知道谁依赖谁的地方
                        └──────┬───────┘
                               │
        ┌──────────────────────┼──────────────────────┐
        ▼                      ▼                      ▼
  ┌───────────┐         ┌───────────┐          ┌────────────┐
  │   core/   │         │    ui/    │          │   data/    │
  │ 基础设施  │◀────────│  视图层   │─────────▶│  内容数据  │
  └───────────┘         └─────┬─────┘          └────────────┘
                              │                       │
                              ▼                       ▼
                     ┌─────────────────┐      ┌────────────┐
                     │  quiz-types/    │      │   art/     │
                     │   题型引擎      │      │  插画资源  │
                     └─────────────────┘      └────────────┘
```

**依赖只允许自上而下，不允许反向或横向。** 具体说：

| 模块 | 可以依赖 | 禁止依赖 |
|---|---|---|
| `core/` | 只依赖浏览器 API | 任何业务模块。core 不认识「知识点」「领域」这些概念 |
| `data/` | 无 | 不 import 任何 UI 或 core 模块。纯数据 + 纯查询函数 |
| `art/` | 无 | 同上 |
| `quiz-types/` | `core/dom`、`core/util` | 不 import `data/`、`ui/`。题型不认识具体内容 |
| `ui/` | `core/`、`data/`、`art/`、`quiz-types/` | UI 模块之间不互相 import |
| `main.js` | 全部 | —— |

为什么这条纪律重要：`core/store.js` 一旦 import 了 `data/`，它就再也不能被单独测试；`quiz-types/choice.js` 一旦认识某个具体知识点，换主题时就要改代码。**依赖方向一旦破口，模块化就只剩形式。**

## 二、各模块职责

### core/ —— 基础设施

| 文件 | 职责 | 关键设计 |
|---|---|---|
| `dom.js` | 极简元素构建（`h` / `render`） | 走 `createElement` 而非拼 `innerHTML`，从结构上杜绝注入。将来换虚拟 DOM 只需改这一个文件 |
| `store.js` | 学习进度唯一数据源 | **v3 加 `learnedAt`**（间隔重复基础），`storage` 与 `now` 都可注入便于测试；脏数据一律降级为空，绝不让应用因数据损坏崩掉；版本字段在数据里、**不换 STORAGE_KEY**（换 key = 用户进度清零） |
| `prefs.js` | 应用偏好（年龄档位） | 与 `store.js` **分开存储**，理由见第四节第 6 条。非法档位静默忽略而非抛异常 —— UI 不该因为一个笔误白屏 |
| `router.js` | hash 路由 | **不认识任何业务**，只把 hash 交给调用方解析。改路由规则不用动核心层 |
| `speech.js` | 语音朗读抽象 | 浏览器用 Web Speech API；打包成 APK 后换成原生 TTS 插件，只改这一个文件 |
| `util.js` | 纯函数（`seededShuffle` 等） | 无副作用，单测全覆盖 |

### ui/ —— 视图层

| 文件 | 对应界面 |
|---|---|
| `shell.js` | 顶栏 + 主容器，只有这两个固定区域 |
| `home.js` | 首页：六大领域卡片 + 「我的地图」入口（复习态加橙色描边） |
| `age-bar.js` | 档位切换条，从 home.js 抽出（地图页也要用） |
| `map.js` | 「我的地图」：4 主题分组（GROUPS）+ 6 SVG 岛 + 65 驿站（4 态：done/review/next/todo）+ 地形装饰 |
| `topic.js` | 领域页：该领域下的知识点列表 |
| `card.js` | 知识点详情：插画 + 一句话 + 三条事实 + 两个按钮 |
| `quiz.js` | 答题浮层容器 |

**`ui/` 之间的纪律**：模块互不引用，只共用 core 与 data 层。`age-bar.js` 从 `home.js` 抽出就是这个原因 —— 地图页也需要档位条，但 `map.js` 不该 `import home.js`。

**`quiz.js` 的职责边界值得单独说明**：它负责反馈文案、进度写入、按钮行为；题型模块只负责「渲染题目」和「判定对错」。这样新增题型时不用重复实现反馈逻辑，也不会出现各题型反馈不一致。

### quiz-types/ —— 题型引擎

四种题型：`choice`（三选一）、`listen`（听音选词）、`order`（排序）、`match`（配对）。

每个题型模块的契约：

```js
export default {
  id: 'choice',
  name: '三选一',
  validate(quiz, ctx) { return []; },        // 返回错误信息数组，空数组 = 合法
  create(quiz, api) { return { el }; },      // 渲染，通过 api.onAnswer 上报结果
};
```

`api` 由答题容器注入：`{ speak, onAnswer, item }`。

### data/ —— 内容数据

每个领域一个文件，导出 `{ id, name, tagline, accent, items }`。`data/index.js` 汇总成注册表并提供查询函数。

**年龄过滤也收在这里**，不让 UI 层各自 `filter`：

```js
getTopicsForAge(band)          // 过滤后的领域列表（空领域会被整个移除）
findTopicForAge(id, band)      // 按档位找领域
listItemsForAge(band)          // 拍平成 [{ item, topic }]
countItemsForAge(band)         // 当前档位的内容总数 —— 进度条的分母
```

**主题分组**（`GROUPS` + `getGroupsForAge`）：4 组（看世界 / 看人类 / 动脑筋 / 学说话），把 6 领域归成「地图上能看到结构」的层。分组写在 `data/index.js` 里，硬编码领域 id 数组——避免和 TOPICS 形成循环。

**为什么是 4 组**：分组要长在能看出结构的地方——这就是地图页。首页 6 张卡不需要分组（每次面对 6 个选项认知负担够低）；地图上要一眼看出「看世界 / 看人类 / 动脑筋 / 学说话」四条线，才需要把 6 个领域收成 4 组。

**新增领域时**：改完 `data/领域.js` 后**必须**去 `GROUPS` 里登记，否则它会从地图页静默消失。`npm run validate` 里有断言兜底。

放这一层的理由：过滤逻辑只有一份，`home.js` 和 `topic.js` 不会各自写一遍然后慢慢走偏。UI 层只调函数，不碰 `ageBands` 字段。

**详情页刻意不过滤**：`findItem(id)` 不带 `band` 参数。孩子正停在一个知识点上、家长切了档位，不该把内容从他眼前抽走。

### art/ —— 插画资源

内联 SVG，按 key 索引。数据层通过 `art: 'science-water-cycle'` 引用，不直接写 SVG。

## 三、一次完整的数据流

以「孩子答对一道三选一」为例：

```
用户点击选项
   │
   ▼
quiz-types/choice.js  pick(index)
   │  ① 标记正确/错误样式
   │  ② 调 api.onAnswer({ correct, detail })
   ▼
ui/quiz.js  onAnswer()
   │  ③ store.recordAttempt(itemId, correct)
   │  ④ store.markLearned(itemId)   ← 答对才标记
   │  ⑤ 渲染反馈文案 + 按钮
   ▼
core/store.js
   │  ⑥ 写入 localStorage
   │  ⑦ 通知所有订阅者
   ▼
main.js  updateStats()
   │  ⑧ shell.setStats("4 / 18")
   ▼
顶栏数字更新
```

关键点：**题型模块从不接触 `store`**。作答与记录之间只有这一条路径，将来要加「家长端统计」只需在 store 上挂订阅，不用改任何题型。

## 四、几个关键决策及理由

### 1. 为什么不用 React / Vue？

这个应用的界面状态极简：一个路由 + 一个进度数字。引入框架要多 40 KB 依赖、一套构建链、以及团队的学习成本，换来的收益接近于零。

真正的复杂度在**内容量**和**题型扩展**上，这两件事框架帮不上忙 —— 它们靠的是数据结构和校验规则。

### 2. 为什么不用 TypeScript，改用 JSDoc？

用 JSDoc 标注 + 编辑器的类型推断，能拿到 90% 的类型提示收益，但**零构建步骤**。

团队现状是「开发初学者 + 项目量很大」，一个改完刷新就生效的工程，比一个要先跑构建、报错信息还看不懂的工程更容易推进。

什么时候该升级到 Vite + TypeScript：内容超过 100 个知识点、题型超过 8 种、或者团队超过 3 人同时改代码时。到那时 `src/` 下的 ESM 代码可以**直接迁移**，不用重写。

### 3. 为什么用原生 ESM 而不是打包？

原生 ESM 让浏览器直接加载模块，代价是必须通过 http 服务打开（`file://` 会被 CORS 拦截）。这个代价可以接受 —— 反正最终要打包成 APK，本来就要起服务。

换来的是：没有构建缓存问题、没有 source map 调试、改一行刷新就见效。

### 4. 为什么把校验做成独立命令，而不是靠 code review？

内容错误的形态很特殊：**它不会报错，只会表现为「有点怪」**。答案下标越界了，点上去没反应；听音题的 `opts[a]` 和 `word` 不一致，孩子永远答不对；`art` key 写错了，显示一个问号。

这些在 code review 里极难发现（要逐条对着数据看），但机器一秒钟就能查完。所以把它们全部前移成 `npm run validate`。

**实测有效**：本项目的校验器上线后立刻抓出了两条真实错误 —— 一条是事实文案里的空泛表达，一条是听音题缺题干导致标题空白。这两条都是我写的，人工检查时都漏掉了。

### 5. 为什么 `seededShuffle` 而不是 `Math.random`？

排序题和配对题需要打乱选项。用随机数会导致：

- 同一道题每次顺序不同，孩子困惑（「上次这个在第一个」）
- 出问题时无法复现
- 测试无法断言

改成确定性洗牌后，同一道题永远同一个顺序，但和数据里写的正确顺序不同 —— 既保证了考察效果，又保证了可复现。

### 6. 为什么年龄档位存 `prefs.js` 而不是塞进 `store.js`？

两个东西看着都是「用户状态」，但**生命周期不同**：

| | 进度（store） | 偏好（prefs） |
|---|---|---|
| 是什么 | 孩子学到了哪 | 这个应用怎么用 |
| 家长点「重置进度」时 | 清空 | **保持不变** |
| 变化频率 | 每次答题 | 孩子长一岁改一次 |

混在一个 key 里迟早出现「重置进度顺手把年龄也清了」这种 bug —— 而且很难发现，因为家长重置进度时通常不会去检查档位。

所以两者用不同的 localStorage key，`tests/prefs.test.mjs` 里有一条专门守这个不变式：重置 store 之后 prefs 的档位必须原样。

**为什么不存「孩子几岁」而存档位**：存岁数就要处理「生日过了要不要自动进档」这类问题，而档位是家长的显式选择，没有歧义。孩子长一岁，家长手动改一次即可 —— 一年一次的操作不值得自动化。

## 五、工程链路：源码 / 打包 / 内容素材

这三条链路是分开的，**不要互相依赖**：

```
开发态   index.html + src/**  ──http──▶  浏览器（无构建，改完刷新）
                                    │
PWA      index.html + src/** + sw.js + manifest.webmanifest
                                    │
APK      tools/build-www.mjs ──▶ www/  ──Capacitor──▶  android/ ──gradle──▶ .apk
                                    ▲
内容     tools/fetch-content.mjs ──▶ tools/raw/ ──人工蒸馏──▶ src/data/*.js
```

### 为什么 APK 要单独生成 `www/`

Capacitor 的 `webDir` **不接受项目根目录**，必须指向独立子目录。而本项目没有构建步骤——源码就是产物。

所以 `tools/build-www.mjs` 不做转译、不打包、不压缩，**它是一份文件清单**，不是构建管线。它只干两件事：复制该进包的文件、自检有没有漏。

**与 PWA 的关键差异**：打包 APK 时 **`sw.js` 和 `manifest.webmanifest` 不复制**。原生 App 的资源本来就在本地，Service Worker 没有意义，注册它反而可能干扰 WebView 的资源加载。同一份源码，两套入口清单——这是清单各自的职责，不是重复。

### 为什么内容素材走「构建期抓取」而不是运行时调用

见 `docs/CONTRIBUTING.md` 第四节的详细论证。一句话：**儿童应用不能有运行时外部依赖**——离线、隐私、内容未经审核、API 会挂，四条都是硬约束。

`tools/fetch-content.mjs` 是开发工具，代码不进 APK。抓下来的原始数据在 `tools/raw/`（已 gitignore），蒸馏后写进 `src/data/*.js`，再由 `npm run validate` 把关。

**这个分工的意义**：把「数据可不可信」和「内容写得好不好」拆成两个独立可查的环节。前者靠工具留痕（`fetchedAt` 时间戳 + 原始 JSON），后者靠校验器 + 人工。

## 六、当前状态与下一阶段方向

### 已落地（v1.0）

- **6 领域 × 65 知识点**：生活科普 / 地理军事 / 人文科技 / 逻辑思维 / 空间思维各 10 个，英语 15 个
- **4 题型**：choice / listen / order / match，覆盖率 32/6/15/12
- **年龄分级** `3-5 / 6-8 / 全部` —— 每个 item 标 `ageBands`，首页与领域页按档过滤（详情页刻意不过滤）
- **4 主题分组** `看世界 / 看人类 / 动脑筋 / 学说话` —— 用在「我的地图」上，给 65 个知识点一个能看出关系的层
- **复习机制**（v3）：store 加 `learnedAt`，7 天间隔；地图 4 态视觉（done / review / next / todo）；首页入口橙色高亮「N 个该温习了」
- **岛屿地形装饰**：每岛 2 个小元素（小石 / 小山 / 小树），hash 稳定决定
- **校验器 6 条断言**（含撞色、未分组领域、review SVG attribute 等未来陷阱兜底）
- **94 条单测 + 48 条开包验断言**，四道关（校验 / 单测 / 截图 / 开包）覆盖全流程

### 仍有缺口 / 后续方向

| 项 | 现状 | 建议方向 |
|---|---|---|
| 语音在 Android WebView 中不稳定 | 走 `speechSynthesis`，不可用时静默降级 | 打包 APK 时接 `@capacitor-community/text-to-speech` |
| 内容量 | 65 知识点离"百科"还差得远 | 按 `docs/CONTRIBUTING.md` 第三节的规范继续补；瓶颈在内容审校不在工程 |
| 无家长端 | 只有顶栏一个总进度 | 可加：分领域正确率、最常错、复习日历。**短期不要碰**——先想清隐私边界（我们零外部上报） |
| 知识图谱（按路线） | 现在 65 个点是平铺的 | 真要做得先设计「依赖关系」（前置知识点）。建议先做「下一个」的依赖链（`prerequisite` 字段），不要一步跳到完整图谱 |
| 答错题进度标记 | 答错过的与没答过的一律 todo | 暂缓：对 3-8 岁是负面反馈。如果要加，应该是家长端的事，不是孩子地图上的标记 |
| 跨岛"航线" | 暂未做 | 暂缓：65 个驿站 + 跨岛连线视觉过密反效果 |
| 插画是几何风格 | 辨识度够但不够精美 | 美术同学可替换 `art/index.js` 里的 SVG，key 不变即可 |
| 素材源只有 6 个 | 覆盖物种 / 天气 / 地震 / 航天 / 天文 / 词义 | 维基系 API 网络层不通，已排除；可继续找免鉴权源补 |
| 真机验证 | `adb devices` 无设备 | 需要 Android 模拟器或真机；当前未实跑 |
| `datamuse` 干扰项候选 | 抓回来了但没用上 | 可以做半自动：工具出候选，人工筛掉超纲词后填入 |
