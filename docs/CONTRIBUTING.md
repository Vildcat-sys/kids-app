# 贡献指南

## 一、环境准备

```bash
# 只需要 Node 22+ 和 Python 3（Python 只用来起本地服务）
node -v          # 需 22 以上，见 package.json 的 engines

# 起本地服务（原生 ESM 必须走 http，不能双击打开）
cd kids-app
python -m http.server 8765
# 浏览器打开 http://127.0.0.1:8765
```

没有构建步骤。改完源码刷新浏览器即可。

---

## 二、提交前必跑

```bash
npm run validate    # 内容校验：结构、id、题型、插画引用、年龄档位、sw.js 覆盖
npm run test        # 单元测试
npm run check       # 上面两条一起跑
```

**`npm run validate` 报错就不允许提交。** 它不是形式主义 —— 内容错误在浏览器里只表现为「有点怪」，不会抛异常，靠肉眼审查根本发现不了。

## 三、最常见的任务：加一个知识点

假设要给「生活科普」加一个「彩虹」。

### 第 1 步：画插画

打开 `src/art/index.js`，在 `ART` 对象里加一条：

```js
// 彩虹：七色弧
'science-rainbow': `<svg viewBox="0 0 200 200" xmlns="http://www.w3.org/2000/svg">
  <circle cx="100" cy="100" r="88" fill="#EAF3FB"/>
  <path d="M32 148 a68 68 0 0 1 136 0" stroke="#E24B4A" stroke-width="7" fill="none"/>
  ...
</svg>`,
```

**绘制约定**（必须遵守，否则在卡片里会被切）：

- `viewBox` 固定 `0 0 200 200`
- 最外层先铺一个浅色圆：`<circle cx="100" cy="100" r="88" .../>`
- 所有内容控制在 `r=88` 的圆内，四周留白
- key 命名 `领域-主题`，全小写短横线

### 第 2 步：写内容

打开 `src/data/science.js`，往 `items` 数组里加：

```js
{
  id: 'science-rainbow',
  name: '彩虹',
  pinyin: 'cǎi hóng',
  art: 'science-rainbow',
  ageBands: ['3-5', '6-8'],   // ← 必填，怎么定见下方「第 3 步」
  lead: '雨后太阳出来，阳光被空气里的小水滴折射，就分成了七种颜色。',
  facts: [
    '彩虹有 7 种颜色：红、橙、黄、绿、蓝、靛、紫。',
    '彩虹其实是一个完整的圆，只是站在地面上只能看到上半部分。',
    '看彩虹时太阳一定在你背后，所以早上看不到西边的彩虹。',
  ],
  quiz: {
    type: 'choice',
    q: '看彩虹的时候，太阳在哪个方向？',
    opts: ['背后', '正前方', '头顶'],
    a: 0,
    why: '阳光要从背后照过来，经过前方水滴折射才能形成彩虹，所以太阳必须在背后。',
  },
},
```

### 第 3 步：定年龄档位

每个知识点必须写 `ageBands`，至少归入一个档位。**漏填会被校验器拦下**——因为后果是内容静默消失：孩子切到某个档位，那个知识点就不见了，界面上没有任何提示。

| 档位 | 判据 | 例子 |
|---|---|---|
| `'3-5'` | 看得见、摸得着、能动手；家长配着插画一句话能讲清 | 牙齿、磁铁、数数、对折、大小套嵌 |
| `'6-8'` | 需要想一步、需要比较、带原理或带历史背景 | 守恒、传递推理、四季成因、溶洞、计算机 |

**大部分内容应该同时标两档。** 「磁铁」3 岁能玩、8 岁也能懂磁极，硬归到一档会让另一档白白少一个知识点。

判断「到底该不该给低龄档」，问自己一句：**这句话家长指着插画能不能一句话讲明白？**

- 「蜜蜂有 6 条腿、4 片翅膀」→ 能，指着图数就行 → 两档
- 「地球歪着身子绕太阳转，各地晒到的阳光不一样多」→ 不能，需要先讲地球、再讲公转 → 只给 6-8

**但别全标两档。** 如果所有知识点都写 `['3-5', '6-8']`，切档位就没有任何差别，而界面上看不出来——按钮还在、点击还有反馈，只是内容一模一样。`tests/age.test.mjs` 里有三条断言专门守这个静默失效。

校验器每次都会打印各档位的知识点数量与独占数量，**独占数长期为 0 就说明分档已经退化了**。

### 第 4 步：跑校验

```bash
npm run validate
```

有问题它会直接告诉你哪一条不对、错在哪。改完再跑一次，全绿就提交。

## 四、内容写作规范

这不是文风偏好，是**校验器会检查的硬性规则**：

| 规则 | 原因 |
|---|---|
| `facts` 必须恰好 3 条 | 少于 3 条信息量不足，多于 3 条 5 岁孩子记不住 |
| 每条事实必须有**具体数字或具体事物** | 「很大」「很多」这类词会被校验器警告 —— 孩子无法从中建立任何尺度感 |
| `lead` 不超过 80 字 | 要能一口气读完 |
| `why` 要回答「为什么」，不能重复答案 | 答对后读解释是重要的学习环节 |
| `tagline` 不超过 12 字 | 超过会在首页卡片折行，断句位置不可控 |
| `ageBands` 必须非空，且元素只能是 `'3-5'` / `'6-8'` | 漏填会让内容在**每个**档位下静默消失；非法值会被静默忽略，同样是「内容不见了但没人报错」 |
| 选项不能重复 | 两个一样的选项会让孩子以为题目坏了 |
| 听音题的 `opts[a]` 必须等于 `word` | 否则这道题永远答不对 |

**写作语气**：像跟孩子面对面说话。不用「应当」「必须」，用「你可以试试」「猜猜看」。不写恐吓式表达（「不刷牙就会烂掉」改成「牙齿上的细菌会产酸，酸会蛀出小洞」）。

### ⚠️ 带数字的事实必须可溯源（本项目最容易出错的地方）

科普数字**写错了没人看得出来**——浏览器不报错，校验器也查不出「13 小时」是不是真的 13 小时。唯一的防线是数据可溯源。

**规矩：`facts` 里凡是带具体数字的，必须来自 `npm run fetch` 的实测抓取，不能凭记忆写。**

```bash
npm run fetch            # 抓全部素材源
npm run fetch -- gbif    # 只抓某一个
```

原始结果落在 `tools/raw/*.json`（已 gitignore，不入库），每个文件都带 `fetchedAt` 时间戳。写完内容后，在 `src/data/*.js` 的注释里标明数据来源。

**现有素材源：**

| 源 | 提供什么 | 用在哪 |
|---|---|---|
| `gbif` | 学名核对界门纲目科属种，`matchType=EXACT` 才算通过 | 物种分类类事实 |
| `weather` | 江门近 7 天实际气温、日出日落 | 天气、季节 |
| `quake` | 近 30 天 M4.5 以上地震 | 地球、自然灾害 |
| `launch` | 真实航天发射记录（型号、机构、结果） | 火箭、航天 |
| `nasa` | NASA 每日天文图标题与说明 | 太空 |
| `datamuse` | 词义关联词，用来给听音题找**同主题干扰项** | 英语 |

**关于 GBIF 的用法（踩过三次坑，务必照做）**

不要用 `q=<中文名>` 去「让 GBIF 告诉你这是什么」。实测三次全错：

| 查询 | 返回的首条 | 实际是什么 |
|---|---|---|
| 蜜蜂 | Melissa yunnanensis（云南蜜蜂花） | 唇形科**植物** |
| 蜜蜂（加界过滤后） | Monoplex vespaceus（蜜蜂法螺） | 一种**海螺** |
| 雪松 | Plantago helleri（雪松車前） | **车前草** |

根因：`q=` 是全文子串匹配，且对中文名的相关性排序很差。**GBIF 是分类学骨架，不是中文名词典。**

正确用法是**反过来**——我方声明学名，GBIF 核对分类：

```
https://api.gbif.org/v1/species/match?name=Ailuropoda+melanoleuca
→ matchType: EXACT   status: ACCEPTED
→ 界 Animalia / 门 Chordata / 纲 Mammalia / 目 Carnivora / 科 Ursidae
```

`matchType` 不是 `EXACT` 或 `status` 不是 `ACCEPTED` 时，工具会带 `warning` 字段，**这种情况下不要把该条数据写进内容**——说明学名可能拼错或已过时异名。

**学名由内容作者负责给出**，工具不负责猜。猜出来的分类学数据宁可不要。

### 关于运行时调用 API（明确禁止）

**应用不在运行时调用任何外部 API。** 四条理由：

1. **离线** 应用定位是 PWA/APK，孩子在车上、飞机上都要能玩
2. **隐私** 儿童应用向第三方发请求，等于把孩子设备的 IP、使用时间送出去
3. **内容安全** API 返回的文本未经审核，儿童应用不能显示未审核文本
4. **可靠性** 免费公共 API 随时下线、限流、改结构

所以链路固定为：**构建期抓取 → 蒸馏 → 落成本地数据文件**。`tools/fetch-content.mjs` 是开发工具，不是运行时依赖，它的代码不会进 APK。

**已知不可用的源**（网络层封锁，两个方向都不通，别浪费时间）：
`wikipedia.org` / `wikidata.org` / `commons.wikimedia.org` / `api.openverse.org`

**代理注意**：本机环境变量里有 `HTTP_PROXY`，但 Node 原生 fetch **不读**它、走直连。实测 `ll.thespacedevs.com`（Launch Library 2）**走代理失败、直连成功**。所以工具里不要给 fetch 加代理配置。

## 五、加一个领域

1. 在 `src/data/` 下新建文件，照现有领域复制结构
2. 在 `src/data/index.js` 里 `import` 并加进 `TOPICS` 数组（顺序即首页顺序）
3. 在 `sw.js` 的 `ASSETS` 里加上新文件路径 ← **最容易忘的一步**，忘了会导致离线状态下加载失败（校验器会检查出来）
4. 补该领域的插画，key 用新领域 id 前缀

`accent` 是领域主题色，会用在卡片左侧色条和标题竖线上。选色建议饱和度偏低、明度适中，避免刺眼。

## 七、常见错误对照表

| 现象 | 原因 | 修复 |
|---|---|---|
| 页面完全空白 | 用 `file://` 打开了 | 改用 `python -m http.server` |
| 某张图显示问号 | `art` key 写错或插画没登记 | `npm run validate` 会指出 |
| 点选项没反应 | `a` 下标越界 | 同上 |
| 听音题永远答不对 | `opts[a]` 与 `word` 不一致 | 同上 |
| 答题框标题空白 | 题型数据缺 `q` | 同上 |
| 离线后白屏 | 新文件没加进 `sw.js` 的 `ASSETS` | 同上 |
| 详情页内容贴边 | 同元素叠类时用了 `padding` 简写 | 只写 `padding-top` / `padding-bottom` |
| 卡片宽度参差 | 网格用了 `auto-fill` | 改成 `auto-fit` |

## 八、代码风格

- **注释解释「为什么」，不解释「做什么」**。`// 遍历数组` 没有价值，`// 用确定性洗牌保证同一道题顺序稳定` 有价值
- 不写 `var`，用 `const` / `let`
- 模块内不产生副作用；需要 DOM 操作的部分集中在 `ui/`
- 新函数写 JSDoc，至少标明参数与返回值
- 提交粒度小、说明写清楚改了什么和为什么

## 九、给新同学的上手路径

按这个顺序做，每一步都能独立跑通，不会卡住：

1. **读**：`docs/ARCHITECTURE.md`，把分层图和依赖方向看懂
2. **改内容**：照着第三节加一个知识点，跑 `npm run validate` 到全绿 —— 这一步不需要懂代码
3. **改样式**：调一个颜色或间距，理解 `src/styles.css` 的变量体系
4. **写测试**：给已有的某个题型补一条边界测试
5. **加题型**：照第六节实现一个新题型
6. **读核心**：这时再回头看 `core/store.js` 和 `ui/quiz.js`，会顺畅得多

第 2 步是最重要的 —— 能独立加内容，就说明理解了数据结构；理解数据结构，后面所有事都顺。**别忘了第 3 步的 `ageBands`**，漏填的内容会在所有档位下消失。
